# metrics-lib v2.1.0 - JSON Without serde

metrics-lib 2.1 writes its JSON snapshot and its OTLP/HTTP JSON request
without serde. Until now both needed the `serde` feature, which brings
`serde` and `serde_json`. Two new features write the same text through
[jsonx-lib](https://crates.io/crates/jsonx-lib) 0.5, a JSON crate with no
dependencies of its own, so a service can export JSON with no serde in its
build. This is an additive release: the `serde` and `otlp` features, the
`Serialize` impls and every existing signature are unchanged, and the new
features do not turn `serde` on.

```toml
[dependencies]
metrics-lib = { version = "2.1", features = ["json", "otlp-json"] }
```

## Added

- **Feature `json`.** `exporters::json::to_json` and `to_json_pretty`, and
  `RegistrySnapshot::to_json` and `to_json_pretty`, write the snapshot
  document of `render` and `render_pretty` and return `String`: writing
  cannot fail, so there is no error to handle.

  ```rust
  use metrics_lib::exporters::json;
  use metrics_lib::LabelSet;

  let core = metrics_lib::MetricsCore::new();
  core.counter_with("requests", &LabelSet::from([("status", "200")])).add(3);
  let body: String = json::to_json(core.registry());
  assert!(body.contains(r#""labels":{"status":"200"},"value":{"type":"counter","value":3}"#));
  ```

- **Feature `otlp-json`.** The OTLP exporter without serde:
  `OtlpExporter::to_json` and the one-shot `otlp::to_json` write the
  OTLP/HTTP JSON request of `render_json`, and `render_protobuf` works as
  before. The serde request model (`OtlpExporter::build` and the
  `ExportMetricsServiceRequest` types) stays with `otlp`.

  ```rust
  use metrics_lib::exporters::otlp::{OtlpExporter, Temporality};

  let core = metrics_lib::MetricsCore::new();
  core.counter("orders").add(2);
  let exporter = OtlpExporter::new("shop").with_temporality(Temporality::Delta);
  let body: String = exporter.to_json(core.registry());
  assert!(body.contains(r#""asInt":"2""#));
  ```

- Both are part of `exporters-all` and `full`.

## The same text

With both writers enabled, the jsonx-lib functions and the `serde_json`
ones write the same bytes for the same snapshot or request: key order,
omitted fields, escaping, indentation, integer and float text, and the
`"NaN"` / `"+Inf"` / `"-Inf"` strings and `null`s for non-finite floats.
The parity tests check it over every metric kind, labels and help text
that need every JSON escape, empty and full histograms and summaries,
exemplars, `u64::MAX`, `i64::MIN`, NaN and the infinities, hand-edited
snapshots that use every kind tag and unit, and 20 000 random floats, in
both the compact and the indented layout; the OTLP request is checked over
both temporalities and repeated exports.

Two details:

- **U+2028 and U+2029.** In a string (a label value, help text, a
  resource attribute) the jsonx-lib writers escape them as `\u2028` and
  `\u2029`; `serde_json` writes them raw. Both are valid JSON and decode to
  the same string, and only the escaped form is safe inside a `<script>`
  block or a JavaScript string before ES2019. This is the only difference.
- **Float text.** jsonx-lib's own float text differs from `serde_json`'s
  in two places: the `+` of a positive exponent (`1e16` against `1e+16`),
  and values exactly halfway between two shortest texts, where
  `serde_json` keeps the even last digit (`164696460098373.625` is
  `164696460098373.62`). The exporters lay floats out themselves to match
  `serde_json` 1.0.147 and later; a direct comparison over 400 000 floats
  runs in the test suite. `serde_json` up to 1.0.146 wrote `1e16`, so
  with such an old lockfile `render` and `to_json` differ there.

## Dependencies

- `jsonx-lib` 0.5 (optional, features `json` and `otlp-json`; default
  features off). No dependencies of its own, MSRV 1.85,
  `#![forbid(unsafe_code)]`, `Apache-2.0 OR MIT`. It is a private
  dependency: none of its types or traits appear in metrics-lib's API, so
  a future `jsonx-lib` line can be taken in a minor release.

## Performance

`json_bench`, a 159-series service registry (about 31 KB of JSON),
Criterion medians on the reference host (AMD Ryzen 9 9950X3D, Windows 11,
shared with other builds), two runs:

| Operation | `serde_json` | jsonx-lib |
|---|---|---|
| Write a prepared snapshot, compact | 29-31 µs | 61-72 µs |
| Write a prepared snapshot, indented | 54-55 µs | 68-69 µs |
| Registry to text, snapshot included | 83-86 µs | 105-113 µs |
| OTLP/HTTP JSON request | 329-411 µs | 167-169 µs |

The snapshot is slower to write through jsonx-lib (about 2 times for the
writing alone, 1.3 times end to end); the OTLP request is about 2 times
faster, because it is written straight from the internal model instead of
a serde model built first. Details in
[`docs/PERFORMANCE.md`](../PERFORMANCE.md).
