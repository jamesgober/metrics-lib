# metrics-lib v2.1.1 - JSON Without serde, Now Faster Than serde

In 2.1.0 the JSON snapshot exporter that needs no serde (feature `json`)
wrote the same text as the `serde_json` one in about twice the time. In
2.1.1 it writes the same text in two thirds to three quarters of
`serde_json`'s time. Nothing in the API changes, and the output is the
same, byte for byte.

```rust
use metrics_lib::exporters::json;
use metrics_lib::LabelSet;

let core = metrics_lib::MetricsCore::new();
core.counter_with("requests", &LabelSet::from([("status", "200")])).add(3);
core.gauge("ratio").set(1e16);
let snap = json::snapshot(core.registry());
// The same bytes from both writers, floats included (`1e+16`).
assert_eq!(snap.to_json(), serde_json::to_string(&snap).unwrap());
assert!(snap.to_json().contains(r#""value":1e+16"#));
```

## Changed

- **jsonx-lib 0.5.1.** jsonx-lib now formats floats itself (it used
  `core`'s formatter) and can write them in `serde_json`'s text, so the
  exporter's own float layout is gone: before, every float was formatted
  with `{:e}`, its digits laid out again, a rare tie broken toward the even
  digit, and the text checked as a number token before it was written.
  jsonx-lib 0.5.1 also copies strings that need no escaping in one piece and
  inlines its writer, which is most of the rest of the gain. The OTLP/JSON
  request (feature `otlp-json`) is written the same way.
- **One allocation.** `to_json` and `to_json_pretty` size the output from
  the snapshot (series, label count, histogram buckets, quantiles) before
  writing, instead of growing it by doubling (about a dozen reallocations
  and copies for a 30 KB snapshot).

## The same text

The parity tests are unchanged and pass: with both writers enabled,
`to_json` and `render`, compact and indented, and the two OTLP/JSON
writers, produce the same bytes over every metric kind, every JSON escape,
non-finite floats, 20 000 random floats in snapshots and 400 000 compared
with `serde_json` directly, ties between two shortest texts included. The
one documented difference from 2.1.0 remains: U+2028 and U+2029 are escaped
by the jsonx-lib writers and written raw by `serde_json`.

## Security

No change. Escaping is jsonx-lib's, as in 2.1.0, and its guarantees are
the same in 0.5.1. Float text is a valid JSON number by construction in
jsonx-lib and is still compared with `serde_json`'s here. The size estimate
only sets a capacity: it is bounded by the series count (which the
registry's cardinality cap bounds) and an underestimate just grows the
string.

## Dependencies

- `jsonx-lib` 0.5.1 (was 0.5.0): still no dependencies of its own, MSRV
  1.85, `#![forbid(unsafe_code)]`. A private dependency, as before.

## Performance

`json_bench`, the 159-series service registry (about 31 KB of compact
JSON), Criterion medians, 2.1.0 and 2.1.1 run alternately and the best of
three or four runs kept, on the reference host while it was running other
work (so every time is higher than in a quiet run; compare within a row):

| Operation | `serde_json` | jsonx-lib, 2.1.1 | jsonx-lib, 2.1.0 |
|---|---|---|---|
| Write a prepared snapshot, compact | 39-40 µs | 26 µs | 86 µs |
| Write a prepared snapshot, indented | 72-75 µs | 43 µs | 103 µs |
| Registry to text, snapshot included | 98-116 µs | 98 µs | 153 µs |
| OTLP/HTTP JSON request | 476-494 µs | 177 µs | 236 µs |

A harness that keeps the best of 40 timed batches, six runs alternating
the two builds, gives the compact snapshot at 0.75-0.77 of `serde_json`'s
time for 2.1.1 and 2.19-2.38 for 2.1.0. Details in
[`docs/PERFORMANCE.md`](../PERFORMANCE.md).
