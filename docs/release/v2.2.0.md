# metrics-lib v2.2.0 - Review fixes

**Date:** 2026-11-11 · **Compare:** `v2.1.1...v2.2.0`

Fixes from an independent review. No breaking API change; MSRV unchanged
(1.85); no new dependency.

## Fixed

- One family with hostile label values no longer blinds every other
  family: a per-family series cap (default 5 000) is checked before the
  series cap. Counters, gauges, timers and rate meters refused by a full
  series cap join their family, as the same handle, once a slot frees.
- `MetricsServer` can no longer be held shut by clients that send a
  request and never read: each address gets at most 4 connections, and a
  write that makes no progress for 2 s drops the client. An optional
  bearer token protects `/metrics`.
- A histogram shared by many threads can be striped with
  `Histogram::with_shards` or `Registry::configure_histogram_shards`: 21 to
  36 ns per observation at 8 threads, against 314 to 613 ns unstriped.

## Added

- `Registry::set_family_cardinality_cap`, `family_cardinality_cap`,
  `DEFAULT_FAMILY_CARDINALITY_CAP`.
- `Histogram::with_shards`, `Histogram::shards`, `MAX_HISTOGRAM_SHARDS`,
  `Registry::configure_histogram_shards`.
- `MetricsServer::builder()` with `bearer_token`, `max_connections`,
  `max_connections_per_peer`, `write_stall_timeout`.

## Changed defaults

- One family holds at most 5 000 series (`usize::MAX` restores 2.1).
- `MetricsServer`: 4 connections per client address, 2 s write stall.

Every fix has a regression test.
